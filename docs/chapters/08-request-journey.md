# 08 一个请求的旅程

> 沿真实调用链走一遍 `llm.generate("你好")`。表格最后一列是 vLLM 里对应的位置。

[▶ 在交互版中逐步点击浏览](https://middle-chunjie.github.io/deepinfer-visual-guide/interactive/#journey)

| # | 环节 | 做了什么 | 源码 | vLLM 里对应 |
| --- | --- | --- | --- | --- |
| 1 | `LLM.generate`<br>**把 prompt 交给引擎** | 对每个 prompt 调 `_add_request`：深拷贝 SamplingParams、用 HF tokenizer 编码成 int32 数组，然后进入 `_run_engine` 循环：有未完成请求就 `step()`，否则 `flush_inflight_reqs()` 把 ZOS 在途的最后一步收回来。 | [`deepinfer/entrypoints/llm.py:90`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/entrypoints/llm.py#L90)<br>[`deepinfer/entrypoints/llm.py:168`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/entrypoints/llm.py#L168) | vLLM 的 `LLM.generate` 几乎同名同义；在线服务时请求先到 API Server 进程分词，再经 ZMQ 送进 EngineCore。 |
| 2 | `add_request`<br>**建 Sequence，可能先编译语法** | 多模态请求在这里把图片占位符展开成 IMAGE_PAD token；Engram 模型再生成一份压缩词表下的 token 序列；带 `so_args` 的请求先提交到 xgrammar 线程池，编译完成的回调里才 `scheduler.add_sequence`。 | [`deepinfer/engine/llm_engine.py:472`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/engine/llm_engine.py#L472)<br>[`deepinfer/engine/llm_engine.py:620`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/engine/llm_engine.py#L620) | 对应 vLLM 的输入处理（Processor）+ `EngineCore.add_request`；结构化输出的语法也是异步编译，请求在编译完成前处于等待状态。 |
| 3 | `Scheduler.schedule`（C++）<br>**决定这一步跑谁** | NORMAL 引擎先判断是不是 DP 投票点，投票决定本步做 prefill 还是 decode；prefill 从 waiting 取请求按 token 预算切 chunk 并分配 KV 块；decode 给 running 里每个请求追加块，块不够就抢占，最后用 MTP varlen 算每个请求本步的 seqlen_q。返回 `SequenceMetadata` 列表。 | [`csrc/engine/scheduler.hpp:667`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/csrc/engine/scheduler.hpp#L667)<br>[`csrc/engine/scheduler.hpp:275`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/csrc/engine/scheduler.hpp#L275) | 对应 `vllm/v1/core/sched/scheduler.py` 的 `Scheduler.schedule()`（Python），输出 `{请求: token 数}`，同一步里 decode 与 prefill 块混合。 |
| 4 | `LLMEngine.step`<br>**处理 fork / 多模态 / 下发** | 若调度产生了 state/块克隆（fork 请求）或需要清零的 state，先在 GPU 默认流上执行；拉取多模态预处理结果；然后 `_run_workers("execute_model_step")`。CP&gt;1 时这个方法名和参数会先通过共享内存广播给 follower 进程。 | [`deepinfer/engine/llm_engine.py:860`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/engine/llm_engine.py#L860)<br>[`deepinfer/worker/base.py:290`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/worker/base.py#L290) | 对应 `EngineCore.step`：调度 → 执行器 `execute_model` → 处理输出，是 EngineCore 进程里的忙循环。 |
| 5 | `Worker.execute_model_step`<br>**四段式：forward → 收上一步 → sample → 收本步** | ① 发射当前步 forward（ZOS 时先在 GPU 上修正 seqlens）；② 对上一步做后处理（这里才第一次等 GPU）；③ 发射当前步 sample；④ prefill 步或关闭 ZOS 时立即后处理当前步，否则留到下一步。 | [`deepinfer/worker/worker.py:89`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/worker/worker.py#L89) | 对应 `GPUModelRunner.execute_model`；开 `--async-scheduling` 时 vLLM 也把本步输出的拷回放到下一步之后处理。 |
| 6 | `ModelRunner`<br>**准备输入，选 CUDA Graph** | 由 C++ 准备 `InputMetadata`（位置、块表、SWA 索引、Engram n-gram id…）。decode 步按总 token 数在分桶里选最小的够用的 graph，不足部分用 padding 序列补齐后 `replay()`；prefill 走 eager。整个函数禁止任何 CUDA 同步。 | [`deepinfer/worker/model_runner.py:308`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/worker/model_runner.py#L308)<br>[`deepinfer/worker/cuda_graph_runner.py:41`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/worker/cuda_graph_runner.py#L41) | 对应持久化 batch 的增量更新 + attention backend 的元数据构建；CUDA Graph 由 dispatcher 在整图与分段图之间选择。 |
| 7 | `DeepseekModel.forward`<br>**40 层 forward** | embedding（prefill 时替换图像位置）→ 40 × [Engram? → HC pre → 注意力 → HC post → HC pre → MoE → HC post] → 末端 HC 混合 → RMSNorm。顺便把 layer 37–39 的特征写进 DSpark 草稿层的 KV。 | [`deepinfer/model_executor/models/deepseek.py:154`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/model_executor/models/deepseek.py#L154)<br>[`deepinfer/model_executor/models/decoder_layer.py:97`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/model_executor/models/decoder_layer.py#L97) | 对应 `vllm/model_executor/models/` 下的模型文件（如 DeepSeek-V2/V3 的实现），用通用的 Linear、Attention、FusedMoE 层拼成。 |
| 8 | `model.sample`<br>**验证草稿 + 生成新草稿** | lm_head 出 logits → 结构化输出 mask → 温度/top-p/top-k → 对每个草稿做拒绝采样、在第一个拒绝处重采样 → 用刚得到的 token 跑 DSpark 3 层，一次出 5 个新草稿和置信度，存进 MTP 信息池供下一步用。 | [`deepinfer/model_executor/models/deepseek.py:383`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/model_executor/models/deepseek.py#L383)<br>[`deepinfer/model_executor/layers/sampler.py:114`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/model_executor/layers/sampler.py#L114) | 对应 `Sampler` + `RejectionSampler`，之后调用草稿器（如 EAGLE 的 proposer）生成固定个数的草稿。 |
| 9 | `post_process`<br>**结果回到 CPU** | 等 `sample_end_evt` 后调 `LLMEngine.post_process`：`process_MTPInfo` 记录新草稿和累乘接受率，`scheduler.process_outputs` 追加 token、判停、回填 KV 计数；把实测的 forward/sample 耗时喂回 varlen 的估时模型。 | [`deepinfer/engine/llm_engine.py:984`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/engine/llm_engine.py#L984)<br>[`csrc/engine/scheduler.hpp:872`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/csrc/engine/scheduler.hpp#L872) | 对应 `Scheduler.update_from_output`：追加 token、判停、释放结束请求的块。 |
| 10 | `RequestOutput`（C++）<br>**打包输出** | `build_request_outputs` 从对象池取 RequestOutput（每个 token 一条，含 logprob、draft_tok/accept_tok 统计），以指针数组返回；资源在下一步的 `pre_sampler_sync` 里延迟释放，与 GPU 计算重叠。 | [`deepinfer/engine/llm_engine.py:743`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/engine/llm_engine.py#L743)<br>[`deepinfer/engine/llm_engine.py:67`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/engine/llm_engine.py#L67) | 对应 API Server 进程里的 `OutputProcessor`：反分词、组装 RequestOutput、流式返回，与 EngineCore 在不同进程。 |

> [!NOTE]
> <strong>关键结构：</strong>每一步引擎都返回 `RequestOutput` 的 C++ 指针数组（`np.uint64`），对象由对象池管理、下一步自动回收，所以 `LLM._run_engine` 必须先 `RequestOutput.clone` 再保存。这是为了避免每步为成千上万个 token 创建 Python 对象。[`llm.py:168`](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/entrypoints/llm.py#L168)
